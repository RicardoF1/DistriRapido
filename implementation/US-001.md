# Incremento US-001 — Iniciar sesión

## Alcance y decisiones

React/TypeScript/Vite/React Router; NestJS/Swagger; Prisma/PostgreSQL; Compose. Únicamente Rol y Usuario. Sin US-002 ni historias posteriores. La página posterior al login confirma identidad y rol; no es un dashboard.

Stitch aporta referencia visual y SVG propio; el HTML no se trasladó. Componentes AuthLayout, BrandLogo, LoginForm, PasswordField, LoadingButton y ErrorMessage. Tokens CSS centralizados, fuentes locales Outfit/Inter, zoom habilitado, controles táctiles y errores accesibles.

Login con email normalizado y contraseña, Argon2id, estado ACTIVO y rol documentado. JWT HS256, secreto de entorno de al menos 32 caracteres, issuer/audience y caducidad validada (60 segundos a 24 horas). JWT únicamente en memoria, sin persistencia ni refresh token. GET /auth/me comprueba identidad/estado actual. Límite 10 peticiones por minuto y errores de credenciales uniformes; no revela existencia de cuentas. Sin cierre de sesión funcional.

Los cuatro roles documentados se crean mediante bootstrap explícito. No existe una contraseña predeterminada ni un seed automático. Bootstrap impide sobrescribir una cuenta existente. Las restricciones de estado ACTIVO/INACTIVO/BLOQUEADO están en la migración SQL, porque Prisma no expresa CHECK.

## Ejecución local

1. Copiar `.env.example` a `.env` en la raíz. Sustituir todos los placeholders. JWT_SECRET debe ser aleatorio y privado; generar, por ejemplo, con `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"` y guardar únicamente en `.env`.
2. Configurar POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB y DATABASE_URL de la misma base. Para Compose, usar una contraseña aleatoria hexadecimal evita caracteres reservados al construir la URL. En URLs configuradas manualmente, codificar caracteres reservados. Si 5432 está ocupado, ajustar POSTGRES_PORT y DATABASE_URL.
3. Desde raíz: `docker compose up -d postgres`.
4. Desde backend: `npm ci`, `npm run prisma:generate`, `npm run db:migrate`.
5. Configurar BOOTSTRAP_ADMIN_EMAIL y BOOTSTRAP_ADMIN_PASSWORD propios en `.env`; ejecutar `npm run db:bootstrap` desde backend y retirar esas variables después. Contraseña de 12–128 caracteres. Nunca versionar este archivo.
6. Desde backend: `npm run start:dev` (o `npm run build` seguido de `npm start`).
7. Desde frontend: `npm ci`, `npm run dev`.

Frontend http://localhost:5173; API http://localhost:3000; Swagger http://localhost:3000/api/docs. JWT_EXPIRES_IN admite segundos o duración como `15m`. FRONTEND_ORIGIN debe ser el origen exacto del frontend.

Alternativa de contenedores: `docker compose up --build -d` aplica migraciones al iniciar backend. Para crear el administrador, pasar las variables de bootstrap desde el entorno privado de la terminal: `docker compose exec -e BOOTSTRAP_ADMIN_EMAIL -e BOOTSTRAP_ADMIN_PASSWORD backend npm run db:bootstrap`. No escribir secretos literales en comandos compartidos.

En este Windows el lanzador npm global está roto; los comandos se ejecutaron mediante `node 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' <argumentos>` sin modificar la instalación del usuario.

## Prueba manual

1. Abrir /login; probar campos vacíos y email inválido.
2. Introducir email registrado con contraseña incorrecta: debe aparecer error y permanecer en login.
3. Introducir credenciales del administrador creado: debe verse confirmación de acceso, email y rol.
4. Abrir una ruta protegida sin sesión o recargar: debe volver a login (sesión en memoria).
5. En Swagger, ejecutar login; usar el token con Authorize y consultar /auth/me. Token inválido: 401. Campos adicionales: 400. Usuario INACTIVO/BLOQUEADO: acceso denegado.
6. Comprobar teclado, foco de errores, mostrar/ocultar contraseña, zoom y ancho móvil.
